# EdgeDecode：项目交付与岗位对应

本仓库是能直接运行的研究原型，并附英文工作论文。它把“算法表示 → 内核执行 → 架构预算”串起来，已经取得 CPU 微基准和合成网络结果。

**当前版本不是完整的 LLM 部署论文。** 不把未测的 GPU/NPU、功耗或面积写成成果。GitHub 可以提交本仓库；论文可以作为早期技术工作稿分享，但不应宣称已在 arXiv 发表或已验证 Arm 全平台。

## 已完成

1. 自定义、明确规定的按行分组对称量化，4/8-bit 真正打包，FP32 scale。
2. C 原生内核直接读取打包权重；单线程 F32 对照；跨 shape、group、precision 的数值校验。
3. Metal 内核与持久化缓冲区宿主程序，已编译；运行环境未提供 GPU，运行结果明确跳过。
4. 三层合成 tanh 网络上的组合质量评估：开发和测试输入分离，每个网络穷举 216 配置。
5. 以实测单算子时延为成本，执行质量与存储约束下的配置选择；再测组合网络时延。
6. CPU-like/GPU-like/NPU-like 三种假设架构的 108 个场景；不把参数当成产品规格。
7. NPU 静态契约检查，能指出格式、activation dtype、group 与 padding 问题；不是厂商编译器。
8. 测试、CI、原始结果、英文 LaTeX/PDF 和中文说明。

## 岗位能力如何展示

| 能力 | 当前证据 | 还不能声称 |
|---|---|---|
| 模型优化 | 分组量化与完整组合误差评估 | 保持了某个真实 LLM 的任务质量 |
| 硬件感知算法 | 成本来自本地 CPU 执行；质量约束参与选择 | 新算法优于成熟方法 |
| 软件原型 | 真正打包读取的 CPU/Metal 源码 | 已达到优化库性能 |
| 架构探索 | 明确假设的吞吐瓶颈与额外面积预算边界 | 已校准到 M4 或某个 Arm NPU |
| PPA | 实测性能；假设能量；归一化面积盈亏条件 | 实测功耗、综合面积或流片结论 |

## 最重要的结果

在设置的相对均方误差门槛 0.005 下，每个合成网络只有 27 个配置合格，均由 8-bit 配置组成。因此当前结果**不支持混合位宽收益**。这不是需要掩盖的失败：它说明必须先有足够质量空间，再讨论低位宽硬件优化。

精度更低也不保证该参考实现更快。编译器行为、解码循环、分组和调用成本共同影响时间；现有数据无法隔离每一项，因此论文不把差值叫作“纯解码税”。
